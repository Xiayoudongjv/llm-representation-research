# Innovation Candidate Registry v1.0

## Registry Metadata

- REGISTRY_NAME = `INNOVATION-CANDIDATE-REGISTRY`
- REGISTRY_VERSION = `1.0`
- ASSET_CLASS = `INNOVATION_CANDIDATE`
- DEFAULT_EPISTEMIC_STATUS = `UNTESTED_PROSPECTIVE_SYNTHESIS`
- SCIENTIFIC_AUTHORITY = `NONE_BY_DEFAULT`
- SUPPORTED_BY_EXISTING_RESULTS = `false` by default unless explicitly scoped as motivation only
- AUTO_PROMOTION_ALLOWED = `false`

This registry is a lower-authority epistemic layer than registered hypotheses, preregistered experiments, canonical scientific results, and supported claims.

## Governance Rules

- ICR-001: Conceptual novelty is not scientific evidence.
- ICR-002: Terminological novelty is not methodological novelty.
- ICR-003: Analogy is not a theoretical bridge.
- ICR-004: A candidate generated by SCAMPER/TRIZ/combination/reverse thinking does not become a scientific hypothesis merely because it is coherent.
- ICR-005: Existing experimental results may motivate a candidate but do not support predictions generated only after those outcomes were observed.
- ICR-006: Candidate activation must obey dependency gates.
- ICR-007: Candidate promotion requires prospective falsifiability.
- ICR-008: Scientific Spine advancement and information gain take priority over idea novelty or aesthetic appeal.
- ICR-009: A candidate may remain permanently unresolved or never activated.
- ICR-010: Failure to activate a candidate does not erase its historical provenance.
- ICR-011: User-originated mathematical intuition must not be silently upgraded into a mathematical theorem or derived consequence.
- ICR-012: AI synthesis must not be retroactively attributed to earlier experiments or to the user unless directly supported by provenance.
- ICR-013: Later terminology must not be retroactively attributed to early work unless an explicit mapping exists.
- ICR-014: An innovation candidate may not modify the interpretation of a completed canonical experiment.
- ICR-015: Innovation candidates must not automatically determine the next experiment.
- ICR-016: Candidate selection for experimentation must occur through a separate scientific route review.

### ACTIVATION_STATE

## Promotion Pipeline

INNOVATION CANDIDATE -> scientific construct defined? -> falsifiable prediction defined? -> dependencies satisfied? -> prior-art sufficiently reviewed? -> HYPOTHESIS LEDGER -> PREREGISTRATION -> EXPERIMENT -> CLAIM LEDGER.

Promotion into the Hypothesis Ledger requires all of:
- Scientifically meaningful construct definition.
- Operationalizable variables/endpoints.
- Falsifiable prediction.
- Dependencies satisfied.
- Claim ceiling defined.
- Prospective test route available.
- Relevant prior-art review completed sufficiently to avoid obvious rediscovery.
- Explicit scientific route-review approval.
- AUTO_PROMOTION = `false`
